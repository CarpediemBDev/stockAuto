### 변경 영향 기록
- 변경 분류: 내부 정리 (런타임 동작·API·스키마 변경 없음). PR #121 감사에서 비차단 지적으로 남긴 항목의 후속.
- 생산자: backend/app/bot/scheduler.py(_persist_harvest_thresholds 말미 두 줄 제거), backend/tests/test_harvest_mode.py(회귀 1건 추가, _run_cycle이 추적 객체를 반환하도록 확장)
- 소비자: 없음. 함수는 표시용 컬럼을 DB에 남기는 역할만 하고 외부 호출자는 스케줄러 자신뿐이다. API 응답·프론트·모바일은 DB 값을 읽으므로 영향이 없다.
- 데이터 경계: DB 쓰기 경로는 그대로다(version 비간섭 Core UPDATE 1건). 제거 대상은 커밋 이후 메모리 객체에 같은 값을 덧쓰던 두 줄뿐이라 저장되는 값과 시점이 달라지지 않는다.
- API 계약: 변경 없음.
- 문서 반영: 영향 없음 - 계약·스키마 문서가 규정하는 것은 컬럼의 의미와 표시 전용 원칙이고, 이번 변경은 그 규정을 지키는 방식만 바로잡는다. 컬럼·응답·판정 규칙이 그대로이므로 고칠 문장이 없다.
- 회귀 테스트: backend/tests/test_harvest_mode.py에 test_threshold_record_leaves_the_shared_holding_clean 1건 추가. 사이클이 끝난 뒤 공유 holding 인스턴스가 dirty가 아님(sqlalchemy inspect(obj).modified is False)을 단언하고, 동시에 DB에는 값이 정상 기록됐는지도 확인한다. 기존 version_id 단언만으로는 이것이 고정되지 않는다 - micro_session이 빠져나가며 expunge_all로 객체를 떼어내 더럽혀진 객체가 flush되지 않고 다음 사이클에 새 객체로 교체돼 증상이 가려지기 때문이다. 네거티브 컨트롤로 제거한 두 줄을 되살리자 이 1건만 정확히 실패했고(modified가 True) 되돌리니 통과했다. python scripts/verify_harness.py 8/8 통과 - pytest 584건, tsc, eslint, Playwright 9건. 앞선 2회는 타 세션(workspace-07) 하네스와의 실행 경합으로 8단계가 BLOCKED이었다. 두 번 다 테스트 단언 실패는 0건이고 webServer 기동 단계에서 next build 락 충돌(Another next build process is already running)로 깨졌다 - 코드가 아니라 경합이 원인이라는 판별 근거다. 해당 세션과 직렬화를 합의한 뒤 락이 빈 상태에서 재실행하자 동일 트리에서 전부 통과했다.
- 미해결 위험: 기능적 위험은 낮다고 판단한다 - 제거한 두 줄은 DB 쓰기가 끝난 뒤 메모리 객체에 같은 값을 덧쓰던 것뿐이라 저장 값과 시점이 달라지지 않고, 중복 쓰기 방지 비교는 사이클마다 DB에서 새로 읽은 값으로 성립한다(운영 경로가 ctx.holdings를 매 사이클 재조회한다). 다만 이 전제가 깨지면(한 사이클에서 같은 보유분을 두 번 처리하거나 ctx.holdings를 재사용하도록 바꾸면) 매 사이클 같은 값을 다시 쓰는 낭비가 생길 수 있다 - 기능 오류는 아니고 UPDATE 한 건이 늘어나는 수준이다.
- 인수인계: 이 두 줄을 다시 넣지 말 것. 매핑 컬럼을 공유 detached holding에 세팅하면 auto-merge가 version_id를 올려 Part B 매도의 db.merge(h)가 StaleDataError로 사이클을 통째 중단시키며, 이는 last_price·highest_price·observed_base_price가 모두 비영속 스냅샷으로 우회하는 이유다. 새로 추가한 회귀 테스트가 dirty 여부로 이것을 고정한다. 하네스 8/8 통과로 검증은 끝났고 상태는 [R](승인대기)다. 다음 시작 지점은 사용자 승인 또는 커밋 트리거다. 커밋 트리거는 아직 받지 않았다 - 커밋 시 AGENTS.md·CLAUDE.md·docs/AI_WORKFLOW.md(타 세션 소유)와 backend/scripts/evaluate_atr_timeframe.py(미완 작업)는 스테이징에서 제외해야 한다.
