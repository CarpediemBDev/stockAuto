FRED 엔드포인트는 실측했다 - DGS2·DGS10·T10YIE 3종이 API 키 없이 HTTP 200으로 열리고 5,919행이 수집된다. 실제 값으로 게이트가 살아나는 것도 확인했다 - 스프레드 0.47, 기대인플레이션 2.31에서 is_recession_alert가 False(침체 아님)로 판정되고, 금리역전 0.1과 저물가 1.5를 주입하면 진입 0점 청산 30점(매도)으로 뒤집힌다. 배선 전에는 두 경우가 구분되지 않았다. 백테스트 열 생산도 무작위 120봉으로 확인했다. 지표 대입은 루프가 아니라 리터럴로 썼다 - 동적 대입은 정적 가드가 생산자를 보지 못해 반려된다(실제로 한 번 반려됐다)
- 미해결 위험: 수집 실패를 캐시하지 않으면 종목마다 재시도해 스캔이 멈춘다. 실패 캐시 10분을 넣고 실측했다 - 실패 상태 100회 호출이 2.27초, 캐시 없을 때는 수십 분이다. 정상 수집은 1.57초이고 캐시 히트 100회는 0.009초다. 다만 FRED가 장기 장애일 때 매크로 필드가 사라져 macro_momentum이 조용히 미진입으로 돌아가며, 그 상태는 로그 경고로만 드러난다. 또한 FRED 발표일과 거래일이 어긋나는 구간은 직전 값으로 채우므로(ffill) 발표 지연 시 하루 묵은 값으로 판정한다. 백테스트는 이제 매크로를 쓰므로 과거 성적이 소급 변경된다 - 배선 이전의 macro_momentum 백테스트 결과와 직접 비교하면 안 된다
- 인수인계: FRED CSV 다운로드는 API 키가 필요 없다(fredgraph.csv?id=SERIES). 시리즈 3종의 의미를 바꾸면 백테스트 성적이 소급 변경되므로 교체 금지다. 매크로는 종목 무관 공통 값이라 스캐너가 스캔당 1회 받아 인자로 주입한다 - build_canonical_metrics 안에서 직접 받으면 종목 수만큼 네트워크를 타고 테스트도 외부 호출에 묶인다. 수집 실패는 반드시 캐시해야 한다. 지표 열 대입은 리터럴 이름으로만 쓴다
