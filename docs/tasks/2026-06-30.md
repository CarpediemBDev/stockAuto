  - **검증 기준**: 매도 완료 후 `BREACH_COUNT_CACHE` 내 3튜플 키가 정확히 pop 소멸되는지 확인하고, 멀티 스레드 동시 수정 상황에서도 충돌이나 데이터 깨짐이 없는지 유닛 테스트로 검증합니다.
- `[x]` **[QA-5] 텔레그램 데몬 동기식 블로킹 해결 및 검증**
  - **세부 설명**: 텔레그램 롱폴링 루프가 메시지를 수신하는 즉시 `ThreadPoolExecutor` 스레드 풀에 위임(`asyncio.to_thread` 또는 `executor.submit`)하여 전체 이벤트 루프 차단을 방지합니다. 또한 KIS API 장애 시 0원 표기 대신 최근 성공 잔고 스냅샷(Latest Balance Snapshot) Fallback을 적용하고 경고 메시지를 발송하도록 구현합니다.
  - **검증 기준**: KIS API 15초 지연/장애 주입 시에도 텔레그램 롱폴링이 마비되지 않고 Fallback 잔고와 지연 안내 메시지가 정상 송출되는지 확인합니다.
- `[x]` **[QA-6] Redis 락 갱신 실패 시 락 증발 및 취소 시 누수 해결 및 검증**
  - **세부 설명**: `_renew_loop`에서 연장 실패 시 0.5초에서 시작하여 최대 3회까지 지수 백오프(Exponential Backoff + Jitter) 재시도를 처리합니다. 임대 만료 시간을 초과하여 락 소유권을 상실(`renewed == 0`)하는 상황이 발생하면 즉시 `CRITICAL_LOST` 상태를 강제 마킹하여 주문 실행기가 거래를 안전하게 긴급 중단하도록 폴링 루틴을 확보합니다. 또한, 상위 비동기 태스크가 취소(`asyncio.CancelledError`)될 때 `release()` 내의 `_renew_task` 취소 대기에서 예외가 전파되어 실제 Redis `DEL` 해제 커맨드 전송이 누락되지 않도록, 전체 해제 과정을 하나의 비동기 함수로 묶어 통째로 `asyncio.shield()`로 감싸 대기 처리합니다.
  - **검증 기준**: 락 갱신 일시 실패 시 백오프로 정상 연장되는지 체크하고, 강제 취소 시그널 인입 시 락 누수가 발생하지 않고 즉시 해제되는지 모킹 로그로 검증합니다.
- `[x]` **[QA-7] SQLite 멀티 인스턴스 DDL 충돌 및 Seeding 레이스 컨디션 해결 및 검증**

  - **검증 기준**: 두 인스턴스가 동시에 기동될 때 DDL 및 Seeding 중복 에러나 DB locked 오류 없이 SQLite 파일락을 통해 안정적으로 초기화가 완수되는지 확인합니다.
